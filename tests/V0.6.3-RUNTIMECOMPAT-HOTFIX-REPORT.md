# Triple Crown v0.6.3 — GSD runtimeCompat Hotfix Report

## User-reported failure

```text
capability install blocked: Cross-capability validation failed:
capability "triple-gstack" runtimeCompat.supported references unknown runtime "claude";
capability "triple-gstack" runtimeCompat.notes references unknown runtime "claude"
```

The failure happens in GSD cross-capability validation before Triple Crown
`triple-gstack` is activated.

## Root cause

v0.6.2 declared a concrete GSD runtime dependency:

```json
{
  "runtimeCompat": {
    "supported": ["claude"],
    "unsupported": [],
    "notes": {
      "claude": "..."
    }
  }
}
```

GSD validates concrete runtime ids against the merged capability registry.
On the reported installation, the merged registry did not expose a runtime
capability with id `claude`, so the third-party feature overlay was rejected.

This is an unnecessary coupling for Triple Crown.

The concrete Claude/gstack/Superpowers requirements are already checked by the
Triple Crown installer and doctor.

## v0.6.3 fix

All three Triple Crown feature capabilities now declare:

```json
{
  "runtimeCompat": {
    "supported": ["*"],
    "unsupported": [],
    "notes": {
      "*": "Triple Crown validates concrete host dependencies in installer/doctor."
    }
  }
}
```

GSD's current capability manifest contract explicitly permits a single
`supported: ["*"]` wildcard for runtime-agnostic feature capability declarations.

This removes the concrete runtime-capability cross-reference while preserving
the installer-level Claude Code dependency checks.

## Installer preflight

Before touching project capability registrations, v0.6.3 now verifies:

```text
all three capability.json files exist
id matches folder
role == feature
manifest version == package version
runtimeCompat.supported == ["*"]
runtimeCompat.unsupported is an array
runtimeCompat.notes contains no concrete runtime id
```

Expected install output now includes:

```text
Capability manifest preflight: PASS
```

## Regression fixture

The fake GSD used by the installer test was strengthened to deliberately reject
any feature capability that contains a concrete `runtimeCompat.supported` or
`runtimeCompat.notes` key with the same error shape as the user report.

Therefore the passing v0.6.3 installer tests exercise this regression directly.

## Recovery from the failed v0.6.2 attempt

No manual deletion is required first.

v0.6.3 install refreshes already-listed Triple Crown capabilities and rewrites
the stable `.triple-crown/` source.

Run v0.6.3 over the same project.

After installation, verify:

```bash
node ~/.claude/gsd-core/bin/gsd-tools.cjs capability list --scope project
```

and:

```bash
node -e "for (const id of ['triple-superpowers','triple-gstack','triple-crown-guide']) { const c=require('./.triple-crown/capabilities/'+id+'/capability.json'); console.log(id, JSON.stringify(c.runtimeCompat)); }"
```

Expected for every capability:

```text
supported = ["*"]
```

## Interrupted-install repair

v0.6.3 always performs a best-effort project-scope removal for each known Triple
Crown capability immediately before reinstalling it. This is intentional repair
logic for a prior installer run that stopped after only some capabilities had
been registered.
