# v0.6.1 Design Notes — Workflow Orientation UX

## Problem

Triple Crown now has enough checkpoints that a user can lose situational context:

```text
PLAN review
execution
code review
evidence freshness
QA
UAT/gaps
security
ship
deployment
Canary
```

The architecture is intentionally multi-plane, so the user should not have to
remember which tool owns the next action.

## Decision

Add a separate read-only capability:

```text
triple-crown-guide
```

with one unified skill:

```text
/gsd-triple-crown
```

Modes:

```text
status
next
resume
help <topic>
map
artifacts
doctor
```

## Why a separate capability

The guide does not belong to gstack or Superpowers.

Putting it in `triple-gstack` would incorrectly make navigation appear to be a
quality-plane responsibility.

The guide is a cross-plane observability/navigation layer.

## Why it has no hooks

The capability declares:

```text
steps: []
contributions: []
gates: []
```

This is deliberate.

A progress/help feature must not accidentally become a new orchestrator or add
blocking lifecycle behavior.

## Source of truth

The guide reads durable project artifacts, not chat history:

```text
.planning/STATE.md
PLAN/SUMMARY
GSTACK-PLAN-REVIEW.json
GSTACK-CODE-REVIEW.json
MUTATION.json
EVIDENCE.json
GSTACK-QA.json
UAT/VERIFICATION
GSTACK-SECURITY.json
RELEASE.json
GSTACK-CANARY.json
```

When Triple Crown deterministic gate scripts are available, the guide invokes
their read-only probes to improve freshness reporting.

## Relationship to GSD progress

Current GSD already has a strong situational command:

```text
/gsd-progress
/gsd-progress --next
/gsd-progress --do "..."
/gsd-progress --forensic
```

Triple Crown does not copy that orchestration/routing system.

Instead:

```text
GSD progress
  = canonical project/phase route

Triple Crown guide
  = external quality/release checkpoint overlay
```

When the current Triple Crown chain is complete, the guide routes back to:

```text
/gsd-progress --next
```

## Ten checkpoint model

```text
1 Plan + plan review
2 Execute
3 Code review
4 Evidence freshness
5 QA-only
6 GSD Verify/UAT
7 Security
8 GSD Ship/PR
9 Deployment evidence
10 Canary
```

Status vocabulary:

```text
DONE
CURRENT
WAITING
BLOCKED
ADVISORY
UNKNOWN
```

## Resume semantics

`resume` reports:

```text
phase
progress bar
current checkpoint
last durable artifact
blocker
next command
```

This is intentionally more durable than relying on the previous conversation.

## Automatic navigation footer

The CLAUDE routing fragment now asks major checkpoint responses to end with:

```text
Checkpoint:
Next owner:
Next:
```

when practical.

This is presentation only. It must not automatically invoke the next lifecycle
command.

## Testing

The guide smoke suite covers:

```text
plan review blocker
execute continuation
code review continuation
QA gap -> GSD --gaps
verify/security -> GSD ship
deployment SHA mismatch recovery
matching deployment -> Canary
Canary complete -> GSD progress next
```

The mock L1 E2E also installs the guide capability and runs it from the staged
`.gsd/capabilities` location before hook assertions.

## Non-goals

v0.6.1 does not add:

```text
automatic next-step execution
new lifecycle scheduler
new state file
new release owner
new fixer loop
```

The invariant remains:

```text
One lifecycle owner = GSD
```
