# v0.2 Design Notes

## Changes from v0.1

### 1. Removed invented `check.query`

v0.1 used placeholder custom query names. GSD 1.10's third-party-safe extension
path is the `command-exit-zero` predicate, so v0.2 uses that shape.

### 2. Removed the premature Superpowers `execute:post` evidence gate

The v0.1 draft attempted to define an evidence query before a durable evidence
schema/checker existed. v0.2 keeps Superpowers integration purely declarative at
`execute:wave:pre`. A deterministic evidence gate belongs in the later mutation/
evidence slice.

### 3. gstack plan review is interactive, not headless

Current gstack `/plan-eng-review` has an anti-shortcut rule: each non-trivial
finding must be handled through interactive questioning. Treating it as a silent
background reviewer would change its semantics.

v0.2 therefore uses:

```text
GSD plan
  -> plan:post gate BLOCKED
  -> interactive /plan-eng-review
  -> approved PLAN settles
  -> digest marker written
  -> plan:post gate PASS
```

### 4. Digest-based approval

The gate hashes the sorted set of all `PLAN.md` / `*-PLAN.md` files in the phase.

Any later PLAN mutation invalidates the approval automatically.

### 5. Superpowers conflict is resolved through explicit project instructions

Superpowers' `using-superpowers` skill says:
- its normal workflow is mandatory;
- but direct human/project instructions (`CLAUDE.md`, etc.) take precedence;
- a specifically dispatched subagent ignores the global `using-superpowers`
  bootstrap.

That gives Triple Crown a clean integration seam:
- GSD dispatches executor subagents;
- project routing explicitly narrows Superpowers to TDD/debugging/verification
  disciplines inside those executors;
- the executor contribution repeats the ownership boundary close to execution.
