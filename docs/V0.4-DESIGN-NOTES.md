# v0.4 Design Notes

## 1. Source-level correction: verify:pre is gate-only

Current GSD `verify-work` explicitly dispatches only `kind == gate` at `verify:pre`.
Therefore QA is not implemented as a verify:pre step.

Correct integration:

```text
execute:post -> qa-only step
verify:pre  -> qa-currentness gate
```

## 2. execute:post ordering

The three external operations share the same extension point but use artifact
dependencies:

```text
review -> QA -> CSO
```

QA consumes `GSTACK-CODE-REVIEW.json`; CSO consumes `GSTACK-QA.json`.

## 3. QA uses GSD's own gap pipeline

GSD gap planning reads canonical `VERIFICATION.md` and `UAT.md`. A separate
QA report alone would be invisible to gap closure.

v0.4 therefore maps QA issues into UAT `## Gaps` with stable `gap_id`.

## 4. QA remediation remains GSD-owned

The default route uses `/qa-only`, never `/qa`.

```text
QA gap
-> GSD diagnosis
-> GSD plan-phase --gaps
-> GSD execute-phase --gaps-only
-> GSD reconciliation/reverification
```

## 5. CSO remains additive

GSD first-party security already produces `SECURITY.md` and blocks ship. gstack
CSO uses `GSTACK-SECURITY.*` and a separate gate; neither can silently override
the other.

## 6. Why CSO also runs at execute:post

Current verify-work has a specific native secure-phase dispatch, not a general
third-party verify:post step loop. `execute:post` is the reliable generic skill
surface for the external audit.
