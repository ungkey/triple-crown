# v0.3 Design Notes

## 1. Why `execute:post` is a skill step

GSD's loop contract dispatches `ref.skill` steps through the host Skill tool.
A capability step must reference a skill stem owned by the same capability.

`triple-gstack` therefore owns:

```text
triple-gstack-code-review
```

and registers it at:

```text
execute:post
```

The skill is the adapter. It invokes the real gstack `/review`; it does not
copy or fork gstack's review methodology.

## 2. Why code review is not a blocking LLM gate

The review itself is non-deterministic and interactive. GSD's step semantics are
the correct place to run it.

The deterministic safety decision is separated into:

```text
verify:pre -> command-exit-zero -> verify-ready.cjs
```

The gate checks artifacts and repository digests, not an LLM opinion.

## 3. gstack may mutate in more than one way

Current gstack `/review` uses Fix-First:
- mechanical findings can be auto-fixed directly;
- other findings can be fixed after user approval.

gstack also has continuous checkpoint mode, which can create WIP commits.

Therefore v0.3 cannot use only:

```text
PRE_SHA vs POST_SHA
```

because uncommitted edits would be missed.

It records a workspace digest containing:
- HEAD;
- staged patch digest;
- unstaged patch digest;
- untracked file digests.

## 4. Why `.planning` and `.gsd` are excluded

The review adapter writes its own artifacts under `.planning`, and installed
capabilities live under `.gsd`.

Including those directories would make:

```text
snapshot -> write evidence -> snapshot changed
```

self-invalidating.

The mutation contract is specifically about the reviewed project worktree.

## 5. Evidence is append-only history plus invalidation

A past passing test is not deleted after mutation.

Instead:

```text
status: passed
validity: stale
```

preserves history while preventing false reuse.

## 6. Latest-result-per-command rule

A verification command can be rerun.

For gate purposes, v0.3 selects the latest evidence for each exact command string.

This supports:

```text
test failed
-> environmental issue resolved
-> exact same test passed
```

without erasing the earlier failure.

A different failing command still blocks.

## 7. Review freshness and verification freshness are independent

Both must hold:

```text
review.postWorkspace == currentWorkspace
AND
fresh verification == currentWorkspace (when review mutated)
```

One cannot substitute for the other.

## 8. Deferred to v0.4

- gstack `/qa-only`
- browser evidence schema
- QA finding normalization
- QA -> GSD gap-plan bridge
- risk-based gstack `/cso`
- security finding -> ship gate
